# 제주 해안 지킴이 지도 (팀 제주쓰담쓰담)

2026 제주 환경 해커톤 출품작. 쓰레기 **양**이 아니라 **생물에게 위험한 순서**로 해안 수거 우선순위를 보여주는 웹앱입니다.

## 화면
1. **위험도 지도** – 제주 수거량 추이(2009~2023), 해안별 위험 지수 지도, 실시간 위험 순위, 기관·언론 정화 기록, 공공데이터로 본 개수 vs 위험 지수 비교, **해안 106개 구역 확인 공백 표시**
2. **쓰레기 제보** – 사진 업로드 → AI(Gemini) 종류 판별 → 제보 → 해안 스탬프
3. **우선 수거 리포트** – 위험 지수 상위 지점, 지킴이·행정 전달용 CSV, 수거 완료 처리(되돌리기 포함), 확인 공백 구역 순찰 목록(CSV), 재확인 권장 지점
4. **가중치 검증** – 가중치 슬라이더, 720개 가중치·보정·반감기 조합 민감도 분석(버튼으로 실행), 요소 간 중복 점검

## 점수
- 현재 위험 지수 = 보정 위해성 × (1 + 돌고래) × 마을어장 × 계절 × 최신성
- 근거 수는 유효 근거 수(검토 전 제보 0.5건, 중복 제보는 1건으로 묶음)
- 최신성: 근거가 오래될수록 가볍게 (반감기 공공 조사 3년, 기관 기록·시민 제보 180일)
- 수거 완료 처리: 완료일 이전 근거는 현재 점수에서 빠지고, 이후 새 근거가 들어오면 다시 순위에 올라옴
- 보정 위해성 = (근거별 위해성 합 + 1×2) ÷ (근거 수 + 1) — 근거가 적은 지점이 한 건으로 튀지 않게 중간값(2) 쪽으로 당기는 축소 추정
- 위해성: 폐어구·로프·낚싯줄 3 / 플라스틱·스티로폼 2 / 해조류·기타 1 (순위 척도. 근거: Wilcox 외 2016, *Marine Policy* 65 — 전문가 274명 평가에서 버려진 어구가 해양생물 위협 1위)
- 돌고래: 대정읍 1.0 (2025 해양생물보호구역 신도리), 안덕면·구좌읍 0.5 (2026 보도)
- 마을어장 500m 이내 ×1.5, 겨울 북서계절풍 토글 시 북·서 해안 ×1.2
- 근거 수 = 공공 조사 + 기관·언론 기록 + 시민 제보 건수

## 확인 공백 ("제보 없음 ≠ 깨끗함")
- 제주 본섬 해안을 마을어장 지선 106개 구역(어장정보도 마을어업, 추자도 제외) + 항만 6곳(제주·서귀포 무역항, 한림·애월·화순·성산포 연안항, 항 중심 반경 800m)으로 나눔 → `zones.geojson`
- 근거(조사·기록·제보)는 자기 위치로, 수거 완료는 지점 위치로 가장 가까운 구역(1.5km 이내)에 붙여 구역별 마지막 확인일 계산
- 순찰했는데 쓰레기가 없으면 '순찰 확인(이상 없음)'으로 기록 → 그 구역은 확인된 것으로 처리되고, 구역 안의 재확인 필요 지점은 수거 완료로 처리 (되돌리기 시 함께 취소)
- 상태: 확인 기록 없음 / 오래전 확인(180일 초과) / 최근 확인
- 순찰 순서: 확인 기록 없음 먼저, 같은 상태 안에서는 민감도(돌고래·마을어장·겨울 북서풍) 높은 곳 먼저

## 기록 저장 (Supabase 무료 DB)
제보·수거 완료·순찰 기록은 Supabase(무료 Postgres)에 저장해 앱 재시작·여러 사용자에도 유지됩니다. 설정이 없으면 앱 폴더의 JSON 파일에 저장합니다 (`store.py`).
1. supabase.com에서 무료 프로젝트 생성 → SQL Editor에서 아래 실행
```sql
create table if not exists public.events (
  id text primary key,
  kind text not null check (kind in ('reports', 'cleanups', 'patrols', 'reviews')),
  data jsonb not null,
  created_at timestamptz not null default now()
);
create index if not exists events_kind_created on public.events (kind, created_at);
alter table public.events enable row level security;  -- 정책 없음 = 공개 키로는 접근 불가, 서버의 secret 키만 접근
grant select, insert, delete on public.events to service_role;  -- 서버(secret 키)만 읽기·쓰기
```
2. Project Settings → API Keys에서 Project URL과 **secret 키**를 복사해 Streamlit Secrets에 추가
```toml
SUPABASE_URL = "https://xxxx.supabase.co"
SUPABASE_KEY = "sb_secret_..."
```
secret 키는 서버(Streamlit)에서만 쓰이고 브라우저로 나가지 않습니다. 테이블은 RLS가 켜져 있어 공개 키로는 읽고 쓸 수 없습니다.
무료 플랜은 1주일 동안 사용이 없으면 일시 정지되므로, 시연 전에 대시보드에서 상태를 확인하세요.

## 기존 업무와 연결 ("또 하나의 앱"이 되지 않게)
- 기존 신고(안전신문고)를 대신하지 않고, 신고·수거 기록을 모아 '어디부터 치울지'를 정하는 판단 도구
- 들어오는 길: 안전신문고 내려받기·바다환경지킴이 실적 CSV 가져오기(양식 제공, 같은 행은 한 번만 반영, 공식 기록은 '확인'으로)
- 나가는 길: 읍면동 브리핑 텍스트(메신저·공문 붙여넣기), 우선 수거 CSV, 위험 지도 GeoJSON(GIS), 제보 전체 CSV
- `?emd=대정읍`처럼 주소로 담당 지역 화면을 바로 열기
- 제보 화면에서 단속이 필요한 건은 안전신문고로 안내

## 허위·중복 제보 대책
- 같은 지점(같은 해변 또는 300m 이내)·같은 종류·24시간 안의 제보는 근거 1건으로 묶음 → 같은 제보를 여러 번 해도 점수가 부풀지 않음
- 같은 사람(익명 세션)이 같은 곳·같은 종류를 24시간 안에 다시 제보하면 거절
- 검토 전 제보는 0.5건으로 계산. 다른 사람이 같은 제보를 하거나 지킴이가 '사실 확인'하면 1건, '허위'면 점수·확인 기록에서 제외
- 검토 전 제보만 있는 지점은 '최근 근거 · 검토 대기'로 표시해 출동 전 확인을 유도
- 기존 DB에는 아래 SQL을 한 번 실행해 검토 기록(reviews)을 허용
```sql
alter table public.events drop constraint if exists events_kind_check;
alter table public.events add constraint events_kind_check
  check (kind in ('reports', 'cleanups', 'patrols', 'reviews'));
```

## 개인정보·보안
- 수집하지 않음: 이름·연락처·계정, 사진(저장 안 함), 기기 GPS. 위치는 사용자가 지도에서 고른 쓰레기 위치만 저장
- AI 판별 시 사진은 Google Gemini 무료 등급으로 전송 → 전송 전 EXIF(GPS·기기 정보) 제거·1024px로 축소, "얼굴·번호판·주소 없음" 확인 후에만 전송
- 메모 칸의 전화번호·이메일·주민번호는 저장 전에 자동으로 가림, 60자 제한
- 제보 검증(종류·읍면동·제주 범위), 세션당 10분 10건 제한, 업로드 10MB 제한
- `ADMIN_CODE`를 Secrets에 넣으면 수거 완료·순찰·되돌리기는 지킴이 코드가 있어야 가능 (없으면 시연 모드로 누구나 가능)
- API 키는 Streamlit Secrets에만 보관(저장소에 없음), DB는 RLS + 서버 전용 secret 키

## 실행
```
pip install -r requirements.txt
streamlit run app.py
```
AI 판별을 쓰려면 `.streamlit/secrets.toml`에 `GEMINI_API_KEY = "..."`를 넣으세요 (Streamlit Cloud는 앱 설정의 Secrets).
무료 한도 보호: 분당 5회·하루 100회 상한, 같은 사진은 재호출하지 않습니다.
